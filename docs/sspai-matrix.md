# 一个为前端工程师而生的 Lottie 压缩工具:把 70MB 的动画压到 1MB

## 起因:被一个动画文件搞崩溃的下午

那天产品同学发来一个 Lottie 文件,语气轻描淡写:

> "就一个加载动画,挺好看的,接一下。"

我点开文件信息——**71.3 MB**。

不是图片,不是视频,是一个 JSON 文件,71.3 MB。

熟悉 Lottie 的人都知道,这是 AE 通过 Bodymovin 插件导出动画的标准格式。**纯矢量的 Lottie 通常只有几十 KB**,加载快得几乎感觉不到。但一旦设计师在 AE 里用了 PNG 帧序列(比如复杂的粒子、烟雾、扭曲特效),Bodymovin 会把每一帧 PNG 用 **base64 编码内嵌**进 JSON。

一个 30 fps 的 5 秒动画 = 150 帧。如果每帧 PNG 是 200KB,这个 JSON 就轻松突破 30 MB。

这种文件根本没法直接上首屏。

## 现成方案为什么都不够用

我查了一圈,能压 Lottie 的工具大致分两类:

**矢量优化工具**(LottieFiles Optimizer、lottie-web 自带的优化):只能砍精度,对纯矢量动画有效,对内嵌 PNG **完全无能为力**。我的文件压完还是 70MB。

**通用 JSON 压缩**(jsoncrush 之类):做的是字符串字典编码,Lottie 播放器根本读不了压缩后的格式。

**在线压缩服务**:基本都有 10MB / 25MB 的上传上限,我这 71MB 根本上传不上去。而且公司动画文件涉及未发布产品,不可能传第三方服务器。

折腾了一下午没解决,索性自己写了一个。

## 工具:lottie-mini

地址:https://www.lottie-mini.com

它做的事情其实就三步:

1. **解析 JSON,找出所有内嵌的 base64 PNG**
2. **把 PNG 解码、按目标质量重新编码为 WebP**(同等画质下体积约为 PNG 的 20%)
3. **可选:按目标帧率抽帧,并重写动画时间轴**(60fps → 30fps 体积再砍一半)

听起来简单,但全部在浏览器端跑——WebAssembly 跑 WebP 编码,主线程之外的 Worker 跑帧解码,不上传任何东西。

把那个 71MB 的文件丢进去,输出 **820 KB**,动画肉眼几乎看不出差别。

## 实际使用流程

1. 打开 https://www.lottie-mini.com,把 `.json` 或 `.lottie` 文件拖进去
2. 选一个预设(WeChat 小程序 2MB / 移动端 H5 1MB / 极致压缩等)
3. 或者手动调质量(60-90)和帧率(15/24/30)
4. 点压缩,等几秒,下载

旁边还有一个 [Preview 工具](https://www.lottie-mini.com/preview),压缩前后可以并排对比播放,确认动画没崩坏才下载——这一步对我而言比压缩本身还重要,因为有时候过激的参数会让动画"看起来还能动但已经变形了"。

## 几个让我最满意的细节

- **完全本地**:没有上传,没有大小限制,没有账号。公司机密素材也可以放心压。
- **支持 dotLottie**:不只是传统 `.json`,新的 `.lottie` 容器格式(zip 包)也能直接读
- **预览能看到资源占比**:打开文件就告诉你 JSON 里有多少 KB 是矢量、多少 KB 是 PNG,一眼看穿这个文件能不能压

## 谁会用得上

- **前端工程师**:接到不合理的动画文件不再需要去找设计师返工
- **设计师**:导出后自己先压一遍再交付,显得很专业
- **小程序开发者**:微信小程序 2MB 限制下,Lottie 几乎是必须压的

## 一些不适合的场景

老实说,这个工具不是万能:

- **纯矢量 Lottie**:本来就小,压不了多少
- **每帧都需要像素级精度的动画**:抽帧会丢细节,这种就别用激进预设
- **动画里有 Bodymovin 的高级表达式**:工具不动表达式,只压资源,但极端情况下可能有兼容问题——所以一定要先用 Preview 对比一遍
